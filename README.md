## Overview

**Databus MCP** is a Model Context Protocol (MCP) server that enables AI assistants and chatbots to access public transportation operational data through standardized interfaces.

It provides structured tools for:

- Public transport operational status.  
- Fleet and route information.  
- Service monitoring.  
- Statistical indicators.  
- Real-time and near real-time transit data.  

The goal of Databus MCP is to expose transit data in a modular, AI-friendly format for operators, regulators, and intelligent systems.

## Repository Structure

This is a monorepo with two main components:
- **`client/`**: Client implementation (Not implemented yet).
- **`server/`**: Python-based MCP server implementation using FastMCP (primary focus).

All Python code and dependencies are in the `server/` directory.

---

## Architecture

### FastMCP Modular Architecture

The project uses the **FastMCP** framework with a **modular subserver architecture**.


**Architecture Overview:**
- `server/databus_server.py`: Main server entry point that imports and composes domain-specific subservers.
- `server/topics/`: Directory containing modular subservers, each focused on a specific domain .
- Each topic module defines an independent FastMCP server instance.
- Subservers are imported into the main server using `mcp.mount(mcp_server_name), namespace="optional_namespace")`.
- This modular architecture makes it easy to extend the system: to add new functionality, simply create a new subserver in `topics/` and mount it in the main server.

### Server Directory Structure

```
server/
├── databus_server.py       # Main entry point - composes and mounts subservers
├── utils/                  # Shared utilities (client, common functions, etc.)
│   ├── common.py
│   └── databus_client.py
└── topics/                 # Domain-specific subservers (modular architecture)
    ├── network/
    │   ├── history.py
    │   ├── network_overview.py
    │   └── realtime.py
    ├── operations/
    │   ├── assignments.py
    │   ├── companies.py
    │   ├── operators.py
    │   └── routes.py
    └── vehicles/
        ├── assignments.py
        ├── information.py
        └── realtime.py
```

## Implementation Status

- The current implementation requires users (or AI LLMs) to know entity IDs, or to use the provided MCP tools to retrieve them.
- MCP tools are based on Databus models up to commit `bb5e4e537005dbdc35b70ca33990205d26d00dd1` ([Databus repository](https://github.com/simovilab/databus)).
- Basic error handling is present, but more robust error management is recommended for production use.
- FastMCP version 3 is used, which is in beta as of February 2026.
- Not all MCP tools are implemented; this is a prototype. Some tools may be simplified, merged, or removed in future versions.
- Certain tools rely on endpoints that may not be optimal for related data retrieval; deeper understanding of the Databus repository may be required for improvements.

## Setup Notes
### Running the MCP Server

```bash
cd server
uv run databus_server.py
```

If you want to use MCP Inspector to test the FastMCP server, you can run:

`uv run fastmcp dev databus_server.py`

For realtime data simulation, see [scripts/README.md](https://github.com/simovilab/databus/blob/main/scripts/README.md).

> **Note:** The Databus MCP client connects to the Databus backend API at http://localhost:8000/ by default. See [server/utils/databus_client.py](server/utils/databus_client.py) if changes are needed


### Sample Data Fixture

Some endpoints do not include sample data by default. To load the fixture:

1. Copy [server/databus_config/feed_sample_data.json](server/databus_config/feed_sample_data.json) into [databus/backend/feed/fixtures/](https://github.com/simovilab/databus/tree/main/backend/feed/fixtures).
2. From the repository root, run:
```bash
`docker compose -f compose.dev.yml exec backend uv run python manage.py loaddata feed_sample_data.json`
```
For realtime data simulation, see [scripts/README.md](https://github.com/simovilab/databus/blob/main/scripts/README.md).


## Integration with AI LLMs

You can test the implemented MCP tools directly with AI LLMs. To integrate the databus-mcp MCP server, follow the platform-specific instructions provided by your AI LLM provider.

#### Cloude Desktop Example Configuration
To connect Databus MCP with Cloude Desktop, add the following to your Cloude Desktop configuration. Replace <PROJECT_DIR> with the path to your project directory:

```json
"mcpServers": {
        "Databus_MCP": {
            "command": "<PROJECT_DIR>/databus-mcp/server/.venv/bin/python",
            "args": [
                "<PROJECT_DIR>/databus-mcp/server/databus_server.py"
            ]
        }
    }
```

This will launch the Databus MCP server for use with Cloude Desktop. Set <PROJECT_DIR> to your local project path, for example: /home/username/Documents/

## Known Issues / Limitations:
- Some endpoints may return incomplete or inconsistent data depending on the Databus backend state.
- FastMCP v3 is in beta; API changes or bugs may occur.
- The system assumes valid IDs are provided; no advanced validation or lookup is implemented.
- Realtime data simulation may require manual setup and is not guaranteed to match production feeds.
- Management of IDs and vehicle license plates requires improvement: values in realtime data and API responses must match exactly to ensure complete and accurate results.
- Input data does not support normalization or fuzzy matching; users must provide exact values, and the system does not handle typos or similar entries.
- The tools need sample data to work
- Some useful MCP tools are not yet implemented
